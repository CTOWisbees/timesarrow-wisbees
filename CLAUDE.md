# TimesArrow (WisBees) — project guide

Public pre-login website for WisBees Investment Advisory, a SEBI-registered, fee-only adviser.
Deployed on Vercel at `timesarrow.wisbees.com`. Phase 1 is the home page only; it must pass
SEBI/BASL content approval. Later phases (onboarding, client dashboard, "Bees Copilot" RAG
chatbot) build on this same app.

## Stack
- Next.js 16 (App Router, Turbopack) + React 19 + TypeScript, pnpm
- Payload CMS 3 running inside the Next app (`/admin`, `/api/*`), Postgres via `@payloadcms/db-postgres`
  (Supabase in production, Mumbai region; local Homebrew Postgres 17 in dev)
- Tailwind CSS v4 (CSS-first tokens in `src/app/(frontend)/globals.css`) + shadcn/ui (radix-nova, `cn` package)
- Recharts via shadcn `chart`, Embla via shadcn `carousel`, react-hook-form + zod 4, Vitest

## Commands
- `pnpm dev` — dev server on :3000 (Payload pushes schema changes to the dev DB automatically)
- `pnpm seed` — load Figma copy into the CMS and create local test users (see `.env`); `SEED_RESET=true` replaces collection docs
- `pnpm test` / `pnpm lint` / `pnpm typecheck`
- `pnpm generate:types` — regenerate `src/payload-types.ts` after any collection/global change
- `pnpm generate:importmap` — after adding custom admin components
- `pnpm migrate:create <name>` — **required after schema changes**; production runs `payload migrate` in `pnpm build`
- `pnpm build:local` — `next build` without migrating

## Layout
- `src/app/(frontend)/` — the website (own root layout). `(payload)/` is generated by Payload; don't edit it.
- `src/payload/` — CMS schema: `collections/`, `globals/`, `access/roles.ts`, `hooks/compliance.ts`, `workflow.ts`
- `src/components/sections/` — one component per home page section, fed by the `home-page` global
- `src/components/shared/` — `CmsImage` (upload or placeholder), `Disclaimer`, `Section`, `RichText`
- `src/lib/queries.ts` — the only place the frontend reads content (Local API, draft-mode aware)
- `src/lib/sip.ts`, `src/lib/format-inr.ts` — calculator math and Indian number formatting (unit tested)
- `src/seed/` — starting content; `public/placeholders/` — labelled placeholder art

## Rules that matter here
- **CMS first.** No marketing or regulatory copy hardcoded in components. Add a CMS field instead,
  seed it in `src/seed/content.ts`, and render it from the global/collection.
- **Compliance workflow.** All public content uses `contentCollection()` / `contentGlobal()` from
  `src/payload/workflow.ts`: drafts + versions, publish allowed only for `compliance`/`admin`
  roles, a sidebar approval record, and `revalidatePath` on publish. New content types must use them.
- **Compliance toggles.** Sensitive elements (expected returns, named holdings, badges, return
  assumptions) are behind CMS checkboxes so compliance can hide them without a deploy. Keep new
  claims of this kind toggleable, and keep a `Disclaimer` next to any figure or projection.
- **Disclaimers are mandatory.** The SEBI disclosure global drives the footer on every page; never remove it.
- **No index before approval.** `SITE_INDEXABLE` must stay `false` until BASL approves the content.
- **Personal data.** Bookings are written only by the server action in
  `src/components/sections/book-call/actions.ts`; REST create/read is closed. Never put PII in URLs or logs.
- Scripts that run outside Next (seed, migrations) must pass `context: { disableRevalidate: true }`.
- Financial projections: truncate, never round up (`formatInrCompact`). The SIP formula is annuity-due
  with monthly compounding at r/12; it reproduces the Figma reference figures (see `sip.test.ts`).
- Site is light-only for now; `dark:` variants only apply under a `.dark` class.

## Roadmap hooks
- Auth/onboarding → new route group `src/app/(app)/`; reuse the Payload `users` collection or Supabase Auth.
- RAG chatbot → `src/app/api/chat/`; pgvector in the same Supabase DB; embed published CMS content
  from Payload `afterChange` hooks.
