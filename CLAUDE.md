# TimesArrow (WisBees) — project guide

Public pre-login website for WisBees Investment Advisory, a SEBI-registered, fee-only adviser.
Deployed on Vercel at `timesarrow.wisbees.com`. Phase 1 is the home page only; it must pass
SEBI/BASL content approval. Later phases (onboarding, client dashboard, "Bees Copilot" RAG
chatbot) build on this same app.

## Stack
- Next.js 16 (App Router, Turbopack) + React 19 + TypeScript, pnpm
- Payload CMS 3 running inside the Next app (`/admin`, `/api/*`), Postgres via `@payloadcms/db-postgres`
  (Supabase in production, Mumbai region; local Homebrew Postgres 17 in dev)
- Tailwind CSS v4 (CSS-first tokens in `src/app/(frontend)/globals.css`) + shadcn/ui (radix-nova, `cn` package)
- Recharts via shadcn `chart`, Embla via shadcn `carousel`, react-hook-form + zod 4, Vitest

## Commands
- `pnpm dev` — dev server on :3000 (Payload pushes schema changes to the dev DB automatically)
- `pnpm seed` — load Figma copy into the CMS and create local test users (see `.env.local`); `SEED_RESET=true` replaces collection docs
- `pnpm test` / `pnpm lint` / `pnpm typecheck`
- `pnpm generate:types` — regenerate `src/payload-types.ts` after any collection/global change
- `pnpm generate:importmap` — after adding custom admin components
- `pnpm migrate:create <name>` — **required after schema changes**; production runs `payload migrate` in `pnpm build`
- `pnpm build:local` — `next build` without migrating

## Layout
- `src/app/(frontend)/` — the website (own root layout). `(payload)/` is generated by Payload; don't edit it.
- `src/payload/` — CMS schema: `collections/`, `globals/`, `access/roles.ts`, `hooks/compliance.ts`, `workflow.ts`
- `src/components/sections/` — one component per home page section, fed by the `home-page` global
- `src/components/shared/` — `CmsImage` (upload or placeholder), `Section`, `RichText`
- `src/lib/queries.ts` — the only place the frontend reads content (Local API, draft-mode aware)
- `src/lib/sip.ts`, `src/lib/format-inr.ts` — calculator math and Indian number formatting (unit tested)
- `src/seed/` — starting content; `public/placeholders/` — labelled placeholder art

## Rules that matter here
- **CMS first.** No marketing or regulatory copy hardcoded in components. Add a CMS field instead,
  seed it in `src/seed/content.ts`, and render it from the global/collection.
- **Compliance workflow.** All public content uses `contentCollection()` / `contentGlobal()` from
  `src/payload/workflow.ts`: drafts + versions, publish allowed only for `compliance`/`admin`
  roles, a sidebar approval record, and `revalidatePath` on publish. New content types must use them.
- **Compliance toggles.** Sensitive elements (expected returns, named holdings, badges, return
  assumptions) are behind CMS checkboxes so compliance can hide them without a deploy. Keep new
  claims of this kind toggleable.
- **Disclaimers live in the footer.** The SEBI disclosure global drives the footer on every page; never remove it.
  Product decision (Oct 2026): no per-section disclaimers or eyebrow/kicker labels above headings.
- **No index before approval.** `SITE_INDEXABLE` must stay `false` until BASL approves the content.
- **Personal data.** Bookings are written only by the server action in
  `src/components/sections/book-call/actions.ts`; REST create/read is closed. Never put PII in URLs or logs.
- Scripts that run outside Next (seed, migrations) must pass `context: { disableRevalidate: true }`.
- Financial projections: truncate, never round up (`formatInrCompact`). The SIP formula is annuity-due
  with monthly compounding at r/12; it reproduces the Figma reference figures (see `sip.test.ts`).
- Site is light-only for now; `dark:` variants only apply under a `.dark` class.

## Client accounts (Supabase Auth)
- `/login` → `/onboarding` live in the `(app)` route group (own root layout, never indexed). Clients sign in with a
  6-digit email code or Google via Supabase Auth; Payload `users` stay staff-only for `/admin`.
- `src/lib/supabase/{client,server,proxy}.ts` + `src/proxy.ts` (Next 16 name for middleware) keep sessions fresh.
  Server code checks the user with `getCurrentUser()` (`getClaims()`), never `getSession()`.
- Applications are the `applications` collection, written only by `src/components/onboarding/actions.ts`, keyed on
  the verified user id. Copy lives in the `onboarding` global.
- Step 2 is the risk-profile questionnaire (`risk-profile` global). **Applicants never see scores**: answer `score` and
  `bands` are field-level staff-only, `getRiskProfileQuestions()` maps them out, and `src/lib/risk-score.ts` scores on
  the server. The application stores a snapshot (answers, score, category, equity limit) for staff review.
- Section designs with alternatives (gallery, onboarding step 2) are registered in `src/lib/section-variants.ts`; the
  live one is a CMS select, others preview in dev via the floating "Variants" menu.
- The same Supabase project is used locally (`http://localhost:3000` in its redirect list); local test accounts appear
  in that project's Auth users.

## Portfolio Scan (`/portfolio-scan`, signed-in `/portfolio`)
- Free scan: upload (CAS PDF read in the browser, broker CSV/XLSX on the server) or manual entry → review →
  optional details → 0–100 score, five sub-scores, red flags R01–R14, charts. Paid plans (Insights ₹99, Pro ₹199) add
  look-through, drag, drawdown, stress, ratios, rebalance, tax, what-if, PDF, alerts.
- Engine is pure TypeScript in `src/lib/portfolio/` (metrics, scoring, rules, paid, ingest; unit tested). Server-only
  code (DB, enrichment, uploads, billing, nightly) is in `src/lib/portfolio/server/`.
- **Gating:** `entitlements.ts#toView` is the only path from a stored result to the browser; locked cards get teasers
  (counts/buckets), never values. Keep it that way for any new paid field.
- Data lives outside Payload in Postgres schemas `market` (instruments, NAV history, benchmarks, look-through) and
  `scan` (portfolios, results, plans, payments, alerts); created by hand-written migrations, RLS on, no public access.
- Copy is the `portfolio-scan` global; thresholds/weights are the `scan-config` global (compliance-owned). The engine
  reads only the *published* config and stores its version with each result.
- Market data: `pnpm market nav` (daily AMFI NAVs), `pnpm market history 400`, `pnpm market benchmarks`,
  `pnpm market stocks <AMFI market-cap xlsx or URL>`, `pnpm market sectors <Nifty 500 csv>`,
  `pnpm market holdings <AMC disclosure xlsx> <amfiCode> [sheet] [asOf]`. Stocks/ETFs/bonds have no licensed price feed
  yet: stocks are valued from what the user types, and index funds stand in for indices (labelled as proxies).
- Nightly: `/api/portfolio/cron` (`pnpm scan:nightly`, `FORCE=1` to re-score everything).
- Demo mode adds "continue as test user" and a plan switcher; payments use Razorpay when its keys are set.
